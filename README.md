# DocChat — Local RAG over your PDFs/Docs

Upload a PDF, DOCX, or TXT file and ask questions about it. Answers are generated by **Groq** (fast Llama models) grounded in your document via **hybrid search** (vector similarity + BM25 keyword search), with **free HuggingFace embeddings**. Storage is **MongoDB Atlas** (free tier works — no special Vector Search index needed, similarity is computed in-app). Built with **LangChain.js** on a **MERN**-style stack.

## Stack

- **Frontend**: React + Vite, Ollama/open-webui-style dark chat UI
- **Backend**: Express + Mongoose
- **Orchestration**: LangChain.js (`RecursiveCharacterTextSplitter`, `ChatGroq`)
- **LLM**: Groq (`llama-3.3-70b-versatile` by default)
- **Embeddings**: HuggingFace Inference API, free tier (`sentence-transformers/all-MiniLM-L6-v2`)
- **Retrieval**: Hybrid search — cosine similarity (vector) + BM25 (keyword), score-fused per query, scoped to the currently selected document
- **Storage**: MongoDB (Atlas free tier, or any MongoDB instance)

## How hybrid search works

For each question:
1. Embed the query with the same HF model used for the document's chunks.
2. Compute cosine similarity between the query vector and every chunk's stored vector.
3. Compute BM25 keyword relevance between the query and every chunk's raw text.
4. Min-max normalize both score sets, combine them as `0.6 * vector + 0.4 * keyword`, and take the top 5 chunks as context for Groq.

This runs in-app in `server/services/hybridSearch.js` — no Atlas Search index configuration required, so it works on any MongoDB tier.

## Setup

### 1. Prerequisites
- Node.js 18+
- A MongoDB connection string (free cluster at [mongodb.com/atlas](https://www.mongodb.com/atlas))
- A free Groq API key from [console.groq.com/keys](https://console.groq.com/keys)
- A free HuggingFace token from [huggingface.co/settings/tokens](https://huggingface.co/settings/tokens)

### 2. Backend

```bash
cd server
npm install
cp .env.example .env
# edit .env and fill in MONGODB_URI, GROQ_API_KEY, HF_API_KEY
npm run dev
```

Server runs on `http://localhost:5000`.

### 3. Frontend

```bash
cd client
npm install
npm run dev
```

Opens on `http://localhost:5173` (proxies `/api` calls to the backend).

### 4. Use it
1. Open the app — you'll land on the **sign in** page first.
2. Sign in with the single operator account: `admin@test.com` / `password123` (or whatever you set `ADMIN_EMAIL` / `ADMIN_PASSWORD` to in `server/.env`).
3. Click **＋ Upload document**, choose a PDF/DOCX/TXT.
4. Wait for processing (extraction → chunking → embedding — a few seconds for a typical doc).
5. Select it in the sidebar and ask questions in the chat box.

## Authentication

This app ships with a single hardcoded operator account rather than a full user system — appropriate for a personal or internal tool, not a multi-tenant product.

- Credentials live in `server/.env` as `ADMIN_EMAIL` / `ADMIN_PASSWORD`. Change them there (never commit real credentials).
- `POST /api/auth/login` checks the submitted credentials with a constant-time comparison and returns a signed JWT (`JWT_SECRET` in `.env`, 12h expiry).
- Every `/api/documents` and `/api/chat` route requires a valid `Authorization: Bearer <token>` header (see `server/middleware/auth.js`).
- The client stores the token in `localStorage` and attaches it to every request; a 401 anywhere drops the user back to the login screen.
- To support more than one person, replace the hardcoded env-var check in `server/routes/auth.js` with a real `User` model + hashed passwords (e.g. `bcrypt`).

## Notes & tuning

- **First HF request may be slow (~20s)**: the free Inference API "cold starts" a model on first call; the embed code retries automatically while it warms up.
- **Chunking**: 1000 chars/chunk, 150 overlap — tune in `server/services/textSplitter.js`.
- **Hybrid weighting**: change `alpha` (default `0.6`, vector-weighted) in `server/routes/chat.js`.
- **Swap the Groq model**: set `GROQ_MODEL` in `.env` to any model listed at [console.groq.com/docs/models](https://console.groq.com/docs/models).
- **Scaling up**: for large document collections, the in-app cosine similarity loop should be swapped for MongoDB Atlas `$vectorSearch` — the `Chunk` schema already stores `embedding` arrays, so you'd just add a vector index in Atlas and replace the loop in `hybridSearch.js` with a `$vectorSearch` aggregation stage.
